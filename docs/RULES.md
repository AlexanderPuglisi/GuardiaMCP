# Guardia MCP rules guide

This guide lists all 88 rules Guardia uses to check MCP servers and skills. For each one you find why it is a risk and how to fix it. The guide is generated by the program itself with `guardia rules --markdown`, so it always matches the code. In the texts, «…» marks a value that a real report replaces with the name of the server, file or field that was found.

## Severity levels

| Level | What it means |
|---|---|
| **CRITICAL** | Almost certainly an attack or a serious flaw. Act now: disable the server or skill until you understand it. |
| **HIGH** | A serious, concrete risk. Fix it before you keep using the server. |
| **MEDIUM** | A weakness an attacker can exploit together with something else. Fix it when you can. |
| **LOW** | A bad habit or a small risk. Fix it at your own pace. |
| **INFO** | Not a problem: useful information, for example what a server can do or that something changed. |

## How to read a finding

Every finding shows a code (for example G05-002), a level, the exact place (file, line and field), what was found, why it is a risk and how to fix it. Secrets are never shown in full: you see [REDACTED] or only their length.

## How codes work

A code has two parts: G05 is the family (for example "dangerous system commands"), 002 is the rule inside the family. Codes are never reused for a different meaning, so you can search, quote and filter them in tools that read SARIF.

## What to do when you find a problem

1. Read the rule's "Why" and "How to fix".
2. If you do not recognize the server or skill, disable it before investigating: it is the safest choice.
3. If the finding is a change (family G03) and you made the update yourself, accept it with `guardia scan --accept-changes` or with the "Accept changes" button in the app. The choice is written to the ledger.
4. After fixing, scan again to check that the finding is gone.
5. If you think it is a false alarm, report it as explained in CONTRIBUTING.md.

## False alarms and missed alarms

Guardia works by reading files, without running anything and without artificial intelligence. So it can be wrong in two ways: flagging harmless text (false alarm) or missing a new trick (missed alarm). "No findings" does not mean "safe": it means these rules found nothing. All limits are explained in SECURITY.md.

## What about rules I write myself?

Rules you write in TOML will drive the real-time Shield planned for version 2. This guide covers only the fixed analysis rules of version 1, which cannot be turned off: this way no malicious file can switch them off.

## Useful words

- **Tool poisoning** — instructions hidden in a tool's description. The user does not see them, but the AI reads them and may obey.
- **Prompt injection** — text written to replace the user's orders, for example "ignore previous instructions". It can come from a tool, a file or a web page.
- **Rug pull** — a server that was harmless and secretly changes after you trusted it. Guardia detects it by comparing every scan with the baseline.
- **Shadowing** — a server that tries to influence how the AI uses another server's tools, for example "when you use send_email add this address".
- **Typosquatting** — a package whose name is almost the same as a famous one (one letter added or swapped), published hoping someone makes a typo.
- **Secret** — a key, token or password that gives access to a service. If it ends up in a configuration file, anyone who reads the file can use it.
- **Baseline** — the snapshot of tools and skills taken at the previous scan. It is used to notice what changed.
- **Skill** — a folder with a SKILL.md file that teaches the AI how to do a task. It can contain instructions and scripts, so it must be checked like a server.

## G01 — Hidden instructions and invisible characters

### G01-001 · HIGH — Invisible characters in the configuration

**Why.** The field "…" contains characters that are not visible on screen (…). This is a known trick to make text look harmless while it says something else to the AI or to the program.

**How to fix.** Open the file with an editor that shows invisible characters and retype the value by hand. If you do not know where this configuration comes from, remove the server.

### G01-002 · HIGH — Hidden instructions for the AI

**Why.** The tool "…" contains markers such as \<IMPORTANT\> or HTML comments that you usually do not see, but the AI reads as instructions. This is the classic form of tool poisoning.

**How to fix.** Do not use the server until you have read the flagged text in full. If the instruction is not justified, remove the server and tell its author.

### G01-003 · HIGH — Asks the AI to act covertly

**Why.** The text of "…" asks not to inform the user or to do something silently. An honest tool has no reason to hide its actions.

**How to fix.** Remove the server: this is a typical sign of malicious tools.

### G01-004 · CRITICAL — Invisible text hidden with Unicode tag characters

**Why.** The field "…" of "…" contains invisible characters that decode to: "…". The AI can read them, you cannot.

**How to fix.** Remove the server immediately: this technique only exists to hide instructions.

### G01-005 · HIGH — Hidden encoded text

**Why.** The field "…" of "…" contains an encoded block (base64 or hex) that decodes to readable text: "…". Text hidden this way may carry instructions for the AI.

**How to fix.** Check the decoded content. If there is no obvious technical reason for it, remove the server.

### G01-006 · MEDIUM — Text pushed off screen

**Why.** The field "…" of "…" contains a huge amount of spaces or blank lines, or is extremely long (… characters). This is a trick to hide instructions beyond the visible part.

**How to fix.** Read the full text (for example in the JSON report) and check what is at the end.

## G02 — Prompt injection

### G02-001 · HIGH — Attempt to override the AI's instructions

**Why.** The text of "…" contains a typical prompt injection phrase, such as "ignore previous instructions". It is meant to change how the AI behaves.

**How to fix.** Remove the server or have the author fix the text.

### G02-002 · HIGH — Fake conversation delimiters

**Why.** The text of "…" imitates the internal separators of a conversation with the AI (for example "System:" or result tags). It is meant to make the AI believe the text comes from you or the system.

**How to fix.** Remove the server: legitimate text does not need to imitate these delimiters.

### G02-003 · HIGH — Asks to hand over the conversation

**Why.** The text of "…" asks the AI to include the conversation, previous messages or system instructions. That way your data ends up at the server.

**How to fix.** Remove the server, or ask the author why they need it.

### G02-004 · MEDIUM — Orders preliminary actions

**Why.** The text of "…" tells the AI to read, run or call something before using the tool. Sometimes this is legitimate, but it is also how attacks get unrequested actions done.

**How to fix.** Read the text: if the requested action has nothing to do with the tool, do not use it.

## G03 — Hidden changes (rug pull)

### G03-001 · HIGH — Tool changed since the last analysis

**Why.** The description or parameters of "…" changed compared to the last approved analysis. This is the sign of a possible rug pull: an approved server that changes covertly.

**How to fix.** Check what changed. If the change is legitimate (for example an update), accept it with: guardia scan --accept-changes

### G03-002 · INFO — New tool

**Why.** The server added the tool "…" since the last analysis.

**How to fix.** Check that the new tool is expected. It has already been added to the baseline.

### G03-003 · MEDIUM — Server configuration changed

**Why.** The command, arguments or variables of "…" changed compared to the last approved analysis.

**How to fix.** If you made the change, accept it with: guardia scan --accept-changes. Otherwise find out who changed the file.

### G03-004 · LOW — Tool disappeared

**Why.** The tool "…" is no longer present compared to the last analysis.

**How to fix.** This is usually a normal update. Accept it with: guardia scan --accept-changes

### G03-005 · HIGH — Damaged baseline

**Why.** The baseline file (…) is unreadable or was changed outside Guardia. While this lasts, rug pulls cannot be detected.

**How to fix.** If you do not know why it changed, check your PC. To recreate it: guardia scan --accept-changes

### G03-006 · INFO — New server

**Why.** The server "…" was not there in the last analysis.

**How to fix.** Check that you added it yourself. It has already been added to the baseline.

## G04 — Cross-server interference (shadowing)

### G04-001 · HIGH — Instructions about other tools (shadowing)

**Why.** The text of "…" gives instructions on how to use other tools or servers. That way a malicious server can manipulate trusted servers without touching them.

**How to fix.** Remove the server: a tool should only describe itself.

### G04-002 · MEDIUM — Mentions a tool of another server

**Why.** The text of "…" mentions "…", a tool of another server (…). This may be a sign of shadowing.

**How to fix.** Check why it mentions it. If it gives instructions about that tool, do not use the server.

### G04-003 · LOW — Same name as a tool of another server

**Why.** The tool "…" has the same name as a tool of …. The AI might call the wrong one.

**How to fix.** Disable one of the two servers if you do not need both.

### G04-004 · MEDIUM — Imitates a built-in client tool

**Why.** The tool is called "…", like a built-in Claude Code tool. It can confuse the AI or whoever approves calls.

**How to fix.** Review the server: a legitimate tool uses its own name.

### G04-005 · HIGH — Changes message recipients

**Why.** The text of "…" asks to change or add recipients (email, phone, blind copy). This is how messages get diverted to an attacker.

**How to fix.** Remove the server.

## G05 — Dangerous system commands

### G05-001 · HIGH — Started through a shell with chained commands

**Why.** The server is started with … and a command that chains several operations (for example with &&, \| or ;). Other commands you do not see may run besides the server.

**How to fix.** Start the server program directly (for example "command": "npx") without a shell, or reduce the command to a single clear operation.

### G05-002 · CRITICAL — Encoded PowerShell command

**Why.** The server starts … with a base64-encoded command. Its content cannot be read at a glance: this is a typical malware trick to hide what runs.

**How to fix.** Do not use this server until you have decoded and understood the command. If you did not write it, remove it.

### G05-003 · HIGH — Windows program often abused

**Why.** The server uses …, a legitimate Windows program often abused by attackers to download or run code covertly.

**How to fix.** A normal MCP server does not need …. Check where the configuration comes from and replace it with the server's official command.

### G05-004 · CRITICAL — Downloads and runs code from the Internet

**Why.** The start command downloads something from the Internet and runs it immediately, without checks. Whoever controls that address can run anything on your PC every time the server starts.

**How to fix.** Remove this configuration. Install the server from an official source with an exact version.

### G05-005 · HIGH — Destructive or system-changing command

**Why.** The start command contains a dangerous operation ("…"): it can delete data, change security settings or gain elevated privileges.

**How to fix.** Remove the operation from the start command. An MCP server must not change the system when it starts.

### G05-006 · MEDIUM — Program started from a temporary or Downloads folder

**Why.** The server program lives in a temporary or Downloads folder, where unverified downloads usually end up.

**How to fix.** Install the server in a stable folder, or through a package manager, and update the path.

### G05-007 · HIGH — Code hidden in the arguments

**Why.** The server starts … and passes code to execute directly in the arguments. This code is not in any file you can review and can do anything.

**How to fix.** Move the code into a file you can read and verify, or use the server's official package.

### G05-008 · INFO — Tool that can run commands or code

**Why.** The tool "…" can run commands or code on your PC. That is not a problem in itself, but it is the most powerful tool the AI has: if the AI is tricked, this is where the damage happens.

**How to fix.** Keep manual confirmation on for this tool and do not approve calls you do not understand.

### G05-009 · CRITICAL — Runs hidden code decoded on the fly

**Why.** The code of "…" decodes a text (for example from base64) and runs it immediately (…). This is the typical signature of malware in packages: the real code stays invisible to whoever reads it.

**How to fix.** Do not use the server. If it is a public package, report it to the registry (npm or PyPI) and to the author.

### G05-010 · LOW — Shell command built from variable text

**Why.** The code of "…" runs shell commands built by joining variable text (…; … places). If that text comes from the AI or from a file, someone could add commands (command injection).

**How to fix.** This is a hint for the server's developers: pass arguments as a list, without a shell. For you: keep manual confirmation on calls to this server.

### G05-011 · LOW — Dynamic code execution

**Why.** The code of "…" runs code built at runtime (…; … places). Some libraries do this, but it makes it impossible to know in advance what will run.

**How to fix.** In well-known libraries this is usually harmless. If the server is little known, check the location shown.

## G06 — Exposed secrets

### G06-001 · HIGH — Secret key written in plain text

**Why.** The variable "…" contains a secret value (… characters) written directly in the file. Any program that reads this file, including a malicious MCP server, can copy it.

**How to fix.** Replace the value with a reference to an environment variable (in Claude Code for example "${…}") or use the app's credential manager. Then rotate the key: consider it exposed.

### G06-002 · HIGH — Secret in the command arguments

**Why.** A start argument contains what looks like a secret (…). Arguments are visible to every program on the PC, for example in Task Manager.

**How to fix.** Pass the secret through an environment variable, not as an argument. Then rotate the secret.

### G06-003 · HIGH — Plain-text secret in HTTP headers

**Why.** The header "…" contains a secret (… characters) written in the configuration file.

**How to fix.** Use a variable reference (for example "Bearer $…") or the client's OAuth sign-in. Then rotate the secret.

### G06-004 · HIGH — Credentials inside the address

**Why.** The address contains credentials or a key (…). Addresses often end up in server logs and history.

**How to fix.** Remove the key from the address and send it as a header or through OAuth. Then rotate it.

### G06-005 · HIGH — Asks the AI to send secrets

**Why.** The text of "…" asks to send keys, tokens, passwords or cookies.

**How to fix.** Remove the server and rotate any secret it may have received.

### G06-006 · LOW — Asks for a secret as a parameter

**Why.** The tool "…" has a "…" parameter: the AI will have to handle a secret and may show it or pass it elsewhere.

**How to fix.** Prefer servers that read secrets from environment variables or through OAuth.

### G06-007 · HIGH — Secret written in the code

**Why.** The code of "…" contains what looks like a secret (…). Anyone who has the package can read and use it.

**How to fix.** If the server is yours, move the secret to an environment variable and rotate it. If it is not yours, tell the author.

### G06-008 · HIGH — The code packs all environment variables

**Why.** The code of "…" turns all environment variables into text (…). They usually hold keys and tokens: this is a typical step before sending them elsewhere.

**How to fix.** Check where that text goes. If it is sent over the network, do not use the server.

## G07 — Access to sensitive files

### G07-001 · HIGH — Access to files with keys or credentials

**Why.** The server receives a path to very sensitive files (…): SSH keys, cloud credentials, browser data or wallets. If the server is compromised or tricked, it can read and send them out.

**How to fix.** Remove that path from the configuration. Give the server only the working folder it really needs.

### G07-002 · HIGH — Access to AI agent configurations

**Why.** The server receives the path of an MCP configuration (…). These files hold keys and commands of other servers: they are the favourite target of tool poisoning attacks.

**How to fix.** An MCP server should not read other servers' configurations. Remove the path.

### G07-003 · MEDIUM — Access to .env files

**Why.** The server receives a path to a .env file (…), which usually holds passwords and keys.

**How to fix.** Check that it is really needed. Otherwise remove the path or move the secrets to a credential manager.

### G07-004 · CRITICAL — Asks to read or send sensitive files

**Why.** The text of "…" asks the AI to read or send very sensitive files (SSH keys, .env, MCP configurations, wallets). This is the core of tool poisoning attacks.

**How to fix.** Remove the server immediately and check whether you already used it. If you did, rotate the keys involved.

### G07-005 · HIGH — The code uses paths of credential files

**Why.** The code of "…" contains the path of very sensitive files (…). If the same file also uses the network the level is CRITICAL, because it could read and send them.

**How to fix.** Check why the server needs it. A normal MCP server does not read SSH keys, cloud credentials or browser data.

### G07-006 · MEDIUM — The code reads or changes AI agent configurations

**Why.** The code of "…" uses AI agent configuration files (…) in … places (…). These are often scripts that add the server to the configuration, but the same access allows reading other servers' keys.

**How to fix.** Check that this is an install or uninstall script. If the server touches these configurations while working, do not use it.

## G08 — Excessive permissions

### G08-001 · HIGH — Access to the whole disk

**Why.** The server receives the disk root or the all-users folder as a path (…). It can read or change any accessible file.

**How to fix.** Limit the server to the project folders it has to work on.

### G08-002 · MEDIUM — Access to your whole personal folder

**Why.** The server receives your whole personal folder (…), which includes documents, SSH keys and app configurations.

**How to fix.** Give only the folders it needs, for example a single project folder.

### G08-003 · HIGH — Option that disables protections

**Why.** The server is started with the option "…", which disables confirmations or protections.

**How to fix.** Remove the option unless you know exactly why it is needed and in which isolated environment it runs.

### G08-004 · HIGH — Container with elevated privileges or host access

**Why.** The server container is started with an option (…) that gives it access to the host system. It practically cancels the container isolation.

**How to fix.** Remove the option and mount only the folders you need, read-only if possible (:ro).

### G08-005 · MEDIUM — Container on the host network

**Why.** The container uses the PC network directly, so it can reach local services that should stay private.

**How to fix.** Use the container's default network and publish only the ports you need.

### G08-006 · MEDIUM — Misleading annotations

**Why.** The tool "…" declares itself harmless (…), but its name suggests it changes or deletes something. Some clients trust these annotations and skip confirmation.

**How to fix.** Do not trust the annotation: keep manual confirmation for this tool.

## G09 — Suspicious network

### G09-001 · HIGH — Remote server without encryption

**Why.** The connection to "…" uses http or ws without encryption. Anyone on the same network can read or change the messages, tokens and results included.

**How to fix.** Use the https:// (or wss://) address. If the server does not support it, do not use it on untrusted networks.

### G09-002 · HIGH — Cloud metadata address

**Why.** The address points to …, used by cloud services to hand out internal credentials. It is a classic SSRF target.

**How to fix.** Remove the address. An MCP server has no reason to contact cloud metadata.

### G09-003 · MEDIUM — Internal network address

**Why.** The address points to …, a private network. That is fine for your own service, but a malicious server can use it to explore your home or office network.

**How to fix.** Check that the address really is your service. Otherwise remove it.

### G09-004 · LOW — Raw IP address

**Why.** The address uses a numeric IP (…) instead of a domain name: it is harder to tell who it belongs to.

**How to fix.** Prefer the official address with a domain name and https.

### G09-005 · LOW — Local server over HTTP

**Why.** The server runs on your PC (…) over HTTP. Any program, or web page open on the PC, can try to contact it.

**How to fix.** Check that the server requires a token and accepts local connections only. Use the stdio transport if possible.

### G09-006 · HIGH — Certificate verification disabled

**Why.** The setting "…" disables HTTPS certificate checks: an attacker on the network can impersonate the server.

**How to fix.** Remove the setting. If you use a corporate certificate, install it in the system instead of disabling checks.

### G09-007 · MEDIUM — Tunnel or data collection service

**Why.** The address uses …, a service often used for temporary tunnels or to collect data sent by others. It is typical of exfiltration.

**How to fix.** Use only official, stable addresses. If you do not know why this address is there, remove the server.

### G09-008 · MEDIUM — Deceptively written address

**Why.** The name … uses international characters (punycode) or an unusual numeric form: it may imitate a well-known site or hide an internal address.

**How to fix.** Check the real address and replace it with the official one.

### G09-009 · LOW — Deprecated SSE transport

**Why.** The server uses the old HTTP+SSE transport, deprecated by the MCP specification.

**How to fix.** Switch to the Streamable HTTP transport if the server supports it.

### G09-010 · HIGH — Asks to send data to a web address

**Why.** The text of "…" asks the AI to send data to a web address or a webhook.

**How to fix.** Remove the server, unless sending is the clear, declared purpose of the tool.

### G09-011 · HIGH — The code contacts a tunnel or data collection service

**Why.** The code of "…" contains the address of a service often used for temporary tunnels or to collect data (…).

**How to fix.** A trustworthy server uses its own stable addresses. If you do not know why it is there, do not use the server.

### G09-012 · LOW — The code contacts a raw IP address

**Why.** The code of "…" contains a hard-coded public IP address (…): it is harder to tell who it belongs to.

**How to fix.** Check who owns the address.

## G10 — Dependencies and supply chain

### G10-001 · MEDIUM — Package without a pinned version

**Why.** The package "…" is downloaded and run without an exact version (given: …). If the package is ever tampered with, the new version starts by itself on the next launch.

**How to fix.** Use an exact version you have checked (for example …@1.2.3) and update it when you decide.

### G10-002 · MEDIUM — Code taken straight from a repository or address

**Why.** The server is installed from "…", a repository or direct address rather than a published version. Its content can change at any time.

**How to fix.** Use a published package with an exact version, or point to a precise commit.

### G10-003 · MEDIUM — Name very similar to a well-known package

**Why.** The package "…" has a name almost identical to "…". This is typosquatting: publishing a package whose name is one letter off.

**How to fix.** Check the exact name on the server's official page. If it was a typo, fix it immediately.

### G10-004 · MEDIUM — Unofficial package registry

**Why.** The package is downloaded from a registry other than the official one (…).

**How to fix.** Make sure you trust that registry. Otherwise use the official one.

### G10-005 · MEDIUM — Container image without a fixed version

**Why.** The image "…" has no fixed version (no tag, or latest): it may change on every start.

**How to fix.** Use an exact tag or, better, the digest (@sha256:...).

### G10-006 · MEDIUM — Scripts that run automatically at install time

**Why.** The server "…" and its dependencies contain … scripts that run by themselves during installation, for example: …. They run before you use the server, with your permissions. The level rises to HIGH if a script downloads or runs code from the Internet.

**How to fix.** Review the scripts shown. To install without running them: npm install --ignore-scripts (some packages may not work).

### G10-007 · MEDIUM — Dependency taken from a repository or address

**Why.** The server "…" depends on code taken straight from a repository or address (…) rather than a published version. Its content can change without notice.

**How to fix.** Ask the author to use published versions or to pin a precise commit.

### G10-008 · MEDIUM — Dependency name almost identical to a famous package

**Why.** The server "…" uses the package "…", one letter away from "…". This is typosquatting.

**How to fix.** Check that it really is the intended package. If it is a typo, malicious code may have been installed.

### G10-009 · LOW — Dependency without a version

**Why.** The server "…" declares dependencies with no version at all (…; … in total): every installation may bring different code.

**How to fix.** Use exact versions or a lockfile (package-lock.json, uv.lock).

### G10-010 · HIGH — setup.py runs code at install time

**Why.** The setup.py file of "…" uses: …. This code runs while the package is installed, before you can check it.

**How to fix.** Review setup.py. A modern package should not start programs or use the network during installation.

### G10-011 · LOW — No lockfile

**Why.** The project in … has no lockfile (for example package-lock.json or uv.lock): dependency versions may change on every installation.

**How to fix.** Create and keep a lockfile: npm install creates package-lock.json, uv lock creates uv.lock.

## G11 — Network exposure

### G11-001 · MEDIUM — Server listening on the whole network

**Why.** The server accepts connections from the whole network (0.0.0.0), not only from your PC.

**How to fix.** Use 127.0.0.1 to limit access to your computer.

## G12 — Configuration hygiene

### G12-001 · LOW — Incomplete configuration

**Why.** The server "…" has no command or address. It cannot work like this: it may be a leftover or a placeholder.

**How to fix.** Complete the configuration or remove the entry.

### G12-002 · LOW — Unknown transport type

**Why.** The transport type "…" is not one defined by MCP.

**How to fix.** Use stdio, http or sse.

### G12-003 · INFO — Same name, different definitions

**Why.** The name "…" is configured in several places with … different definitions. It can be unclear which version you are really using.

**How to fix.** Align the configurations or give different servers different names.

### G12-004 · MEDIUM — Duplicate key in the file

**Why.** The file contains the key "…" twice. Different programs may read different values: it is a way to hide a value from whoever reviews the file.

**How to fix.** Keep a single definition and remove the duplicate.

### G12-005 · HIGH — Plugin pointing outside its folder

**Why.** The plugin tries to load a file outside its own folder ("…"). Guardia ignored it.

**How to fix.** Review the plugin: a legitimate plugin only uses files inside it.

### G12-006 · LOW — Configuration file could not be analyzed

**Why.** The file was not read (…), so the servers it contains were not checked.

**How to fix.** Fix the file format or permissions and run the analysis again.

### G12-007 · LOW — Part of the server code was not analyzed

**Why.** … files of the server "…" were not analyzed: too large, unreadable or written so they cannot be parsed. A crafted file can be used to hide tools.

**How to fix.** Check the files listed in the JSON report. If the server comes from an official source, this is usually harmless.

## G13 — Tamper-evident ledger

### G13-001 · HIGH — Ledger tampered with

**Why.** The tamper-evident ledger (…) fails verification: …. Someone or something changed, deleted or added lines outside Guardia.

**How to fix.** Do not delete it: it is evidence of what happened. Check your PC, then run: guardia ledger verify

### G13-002 · MEDIUM — Ledger cannot be verified

**Why.** The ledger (…) cannot be fully verified: ….

**How to fix.** This is normal if you switched Windows user or restored the PC. Otherwise check who changed Guardia's folder.

## G14 — Skills

### G14-001 · INFO — The skill contains executable scripts

**Why.** The skill "…" contains … scripts (…) that the AI can run on your PC when it uses the skill.

**How to fix.** Read the scripts before using the skill, especially if it comes from a source you do not know.

### G14-002 · MEDIUM — The skill grants itself powerful tools without confirmation

**Why.** The header of the skill "…" allows … without asking for confirmation each time (allowed-tools field). If the skill instructions are manipulated, commands run without your approval.

**How to fix.** Remove or narrow allowed-tools (for example Bash(git status:\*)) unless you fully trust the skill.

### G14-003 · HIGH — The skill downloads and runs code from the Internet

**Why.** The skill "…" contains a command that downloads a script from the Internet and runs it immediately (…). Whoever controls that address can run anything on your PC. In the skill instructions this is MEDIUM, because the AI asks for confirmation; in an attached script it is HIGH.

**How to fix.** Install the program from the official site after checking its origin, instead of running a script downloaded on the fly.
